From interaction to source.

Fieldwork is a synthetic planning workspace built with zg-gui. Its tasks, filters, selection, and activity live in Zig. A small browser host applies the resulting DOM commands.

1. Write a template

Templates describe the shape of the interface. Bindings read a typed view; the native compiler generates Zig projection functions during the build.

<input id="task-title"
       :value="$selected_title"
       :input="$inputs.title">

<tbody :loop="$rows" :key="id" :limit="24">
  <tr data-task="$item.id">
    <td :text="$item.title"></td>
  </tr>
</tbody>

The overview cards invoke the same metric component three times. Each instance has independent bindings and generated node identities.

2. Keep state and ownership explicit

The example owns up to 24 tasks, five activity entries, fixed text buffers, and two 128 KiB rendering buffers. Edits are validated and copied into candidate state. A render only commits that state and its snapshot after both output writers succeed.

var next = state;
// Apply the admitted edit to next.
return render(.{ .candidate = next, .mode = .patch });

Task data has no storage or backend. Reloading starts a fresh sample; only your theme preference is saved in this browser. Search folds ASCII case and matches UTF-8 text byte-for-byte otherwise. User edits allow 48 UTF-16 units for titles/search and 256 for notes, fitting their UTF-8 byte buffers.

3. Update the smallest owner

Changing a title updates its text and form value. Reordering emits move commands for retained keyed rows. The table, detail panel, and unrelated controls keep their DOM identity. Try typing in Notes, then use the Move task controls.

Creation and deletion add or remove individual rows. Changing a filter removes excluded rows; their DOM objects are recreated when they return. Task data remains in Zig throughout.

Increment, Decrement and Reset change only the counter. Decrement stops at zero. Showing the details preserves the paragraph and surrounding controls.

Basics: retained rows

Type a draft into a row, then reverse the visible collection or add a third row. Existing rows move with their inputs intact. Removing a row discards that row's browser-only draft. The same controls update both mapping tables without changing channel choices.

Basics: independent component instances

Both integration panels use the same template, with independent channel values. The separate Remove Email option experiment changes the available options. If Email was selected, a message explains its temporary absence; restoring the option restores the remembered selection unless you chose SMS.
